## 2026-09-08 20:05 — День 1: каркас проекта

```text
Привет. Делаем тестовое задание на вакансию Agentic Developer, это сервис шеринга самокатов. Продукт клиент-серверный, отдельный бэкенд и отдельный фронтенд, общаются по сети, база реляционная. Репозиторий пустой, мы уже в нём.

По стеку я решил так: бэкенд на Python 3.12 с FastAPI, SQLAlchemy 2 асинхронная, миграции через Alembic, база PostgreSQL 16. Фронт на React с Vite, карту берём react-leaflet с OpenStreetMap, чтобы не возиться с api-ключами. Всё должно подниматься одной командой через docker-compose.

Сегодня делаем только каркас, бизнес-логику не трогаем. На бэке структура app/api, app/models, app/schemas, app/services, эндпоинт GET /api/health, подключение к базе из переменных окружения, инициализируй alembic и сразу сделай smoke-тест на health через pytest плюс ruff. На фронте одна страница с картой, центр Бишкек. В docker-compose должны быть postgres, backend и frontend. Ещё нужен .env.example, README с тем как запускать, и CI на GitHub Actions, где линт и тесты бэка и сборка фронта.

Теперь как работаем, это на весь проект. В main первым коммитом кладёшь только README-заглушку и gitignore, дальше вся работа только в фича-ветках типа feature/day1-scaffold, коммиты делай небольшие и осмысленные и перед каждым гоняй тесты с линтом. Когда все критерии этапа выполнены, пушишь ветку и создаёшь pull request через gh pr create, в описании пиши что сделано, как проверить и чеклист. Сам PR не мержи, мержить буду я после ревью, как смержу — переключаешься обратно на main и пуллишь. Ещё заведи DEVLOG.md, куда пишешь решения с датой и временем, что решили и почему, первой записью пусть будет выбор стека с обоснованием. И заведи PROMPTS.md, куда сохраняй мои промпты как есть. Если делаешь какое-то допущение, тоже фиксируй его в DEVLOG.

Проверяем так: docker compose up --build поднимает всё, карта открывается на localhost, /api/health отвечает {"status":"ok"}, тесты и линт зелёные, после пуша CI зелёный и открыт PR с нормальным описанием.
```
